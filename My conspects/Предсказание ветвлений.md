## Проблема

Процессор выполняет инструкции через конвейер (pipeline). Когда встречается условный переход (`if`, `for`, `while`), процессор не знает заранее, какая ветка выполнится. Чтобы не простаивать, он угадывает и загружает инструкции спекулятивно.

Если угадал неправильно — нужно сбросить конвейер (pipeline flush) и откатить всё, что было загружено.

## Конвейер

- Глубина: **15–20 стадий** в современных процессорах
- Стадии: fetch → decode → execute → memory access → write back
- Штраф за промах: **15–20 тактов** = 4 нс при 5 ГГц

## Алгоритмы предсказания

| Алгоритм              | Точность         | Описание                                                                                      |
| --------------------- | ---------------- | --------------------------------------------------------------------------------------------- |
| **1-bit predictor**   | ~99.8% на циклах | Запоминает последний результат                                                                |
| **2-bit counter**     | 85–90%           | Strongly Taken (11) → Weakly Taken (10) → Weakly Not Taken (01) → Strongly Not Taken (00)<br> |
| **2-level predictor** | —                | Branch History Register (12+ бит) + Pattern History Table                                     |
| **TAGE**              | 95–98%           | TAgged GEometric history length, несколько таблиц с разной длиной истории                     |

## Производительность

Пример: цикл с условием `data[j] >= 128`:
- Неотсортированный массив → 50% промахов → **11.2 с**
- Отсортированный массив → 1 промах на границе → **1.9 с**
- Разница: **~6x**

Современные предсказатели дают точность **95–97%**, но оставшиеся 5% промахов могут сильно влиять на горячие участки кода.

## Branchless код

Замена условных переходов арифметикой или битовыми операциями — устраняет ветвление полностью.

Инструкция **`cmov`** (conditional move) — выбирает значение без jump-инструкции, предсказатель не задействуется.

## Spectre

Уязвимость, эксплуатирующая спекулятивное выполнение:
1. Атакующий тренирует предсказатель на корректных данных
2. Затем подаёт «неправильный» адрес
3. Процессор спекулятивно читает защищённую память
4. Данные утекают через side-channel (кэш-тайминг)
